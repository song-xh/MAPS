# 02｜轻量 Demo 需求与验收

修订：2026-09-21。按用户要求，本项目只做算法展示页面；本文件替代上一版完整平台需求。

## 1. 目标和范围

让观众完成五件事：**加载数据、选择算法或模型、观察动态过程、查看结果、查看图表。**

应用在演示者本机启动，浏览器打开即可使用。主体只有“过程演示”和“结果图表”两个标签页。CAMA、DAPA、RL 的细节放在页内切换，不再各建一个工作区。

不建设登录、账号、权限、后台、数据/模型管理、实验管理、任务队列、多用户功能、在线训练和云部署。也不要求通用事件平台、全量候选审计、任意时间点计算分叉或自动实验流水线。

## 2. 最短操作流程

```text
选择数据 ──→ 选择 CAPA / RL-CAPA / 已接入基线
                       │
                       └─ RL-CAPA：额外选择兼容模型文件
                                  ↓
                               开始运行
                                  ↓
                     播放 / 暂停 / 单步 / 拖动进度
                                  ↓
                          查看结果图表
```

另有“加载回放”入口，直接读取已经算好的过程和结果。运行模式与回放模式清楚标记，不把播放旧数据说成实时计算。

首版“动态展示”采用**计算后播放真实过程记录**，无需边计算边推送。若后续确有现场需求，再增加逐批计算逐批显示。暂停、重置、倍速只控制播放，不改算法。

## 3. 必需功能

| ID | 功能 | 最小实现与验收 |
|---|---|---|
| D01 | 加载数据 | 选择本地示例目录或受支持文件，显示数据名、任务数、courier数；地图出现对应对象 |
| D02 | 选择算法 | 下拉选择CAPA、RL-CAPA及已接入基线；普通算法不要求模型文件 |
| D03 | 加载模型 | 仅RL-CAPA显示模型输入；加载权重和配套归一化/配置，检查特征与动作维度；错误则直接提示 |
| D04 | 执行算法 | “开始运行”调用原有算法，计算时禁用重复提交，完成后可回放；只允许一次计算 |
| D05 | 加载回放 | 读取本地过程文件及结果，无需重新训练或执行大实验；页面标“预计算回放” |
| D06 | 动态过程 | 播放/暂停、单步、重置、进度条与倍速；地图、详情、累计指标随同一帧更新 |
| D07 | 算法细节 | 点包裹看本地候选与原因、courier→平台两层竞价；RL模式额外显示批长、动作概率及真实执行结果 |
| D08 | 结果与图表 | TR、准时CR、BPT，以及累计收益、任务状态、批长变化；空数据有明确说明 |

D07只记录演示需要的批次和任务细节。大场景可仅对预选示例包裹保留详细过程，其余展示批次/结果；界面说明记录范围，不强求每个历史任务都有完整决策解释。

## 4. 可选项

完成D01–D08后，按演示效果选择补充，均不作为首版阻塞项：

- 在结果页加载一组已有多算法结果，画TR/CR/BPT对比图。
- 加载已有训练日志，画reward、loss或entropy；不增加训练按钮。
- 调整批长、任务数等少量参数后重新计算，不做在线sweep平台。
- 导出当前图表或CSV，不做实验归档中心。
- 若算一次耗时明显，增加一个本地计算子进程和简单进度；不增加队列或任务管理页。

## 5. 两页分别显示什么

### 页1：过程演示

顶部一行：数据选择、算法选择、条件显示的模型选择、开始运行、加载回放。少量参数放进折叠区。

中部：左侧地图或路网平面图；右侧包裹详情。详情页内切换“本地匹配 / 双层竞价 / RL决策”，后者只在相关算法下出现。上方放3–4项数值卡，下方放播放控制和时间轴。

示例讲解：选一件包裹，查看谁可服务、为何本地接受或进入竞价、哪位courier代表平台、哪家平台获胜和实际付款。RL模式再展示本批时间窗和该任务的去向决策。

### 页2：结果图表

直接显示当前计算/回放的结果，无需保存或登记。首屏展示TR、CR、BPT，配累计收益和完成状态图；下方显示批长/分配数量变化。已有对比和训练日志通过一个文件选择入口加载，以页内图表显示。

点击“返回过程”保留当前进度；两个标签页共享同一份结果。

## 6. 数据和算法展示的底线

这些是数值准确性的基本要求，不要求开发管理功能：

| 项目 | 展示规则 |
|---|---|
| 数据名称 | 按实际加载文件显示；`ny`预设不能自动写成NYTaxi |
| 模型/算法 | 只显示当前执行的方法和模型；不支持任意上传Python脚本或临时设计神经网络 |
| CAMA | 展示实际候选与选择；没有KM执行记录就不画KM动画 |
| RL动作 | 区分策略动作和最终分配；动作0若是先本地再竞价，不显示成直接延期 |
| 未来信息 | 使用真实未来任务特征时用简短“oracle输入”标签说明，不当作已部署预测 |
| 完成率 | 准时完成的本地请求数 / 本次本地请求总数；分配成功不等同于完成 |
| 收益TR | 按已核验规则统计准时完成任务的票价减直接支付，不当作全部运营成本后的利润 |
| BPT | 保留现有平均批次决策耗时定义，图注说明；与批长秒数、完整运行耗时区分 |
| 竞价 | 先courier层FPSA，后平台层RVA；显示获胜报价、支付及相应单/多平台规则 |
| 来源 | 预先选好可核验示例；估算不标实测，均值图不冒充单次地图轨迹 |
| 对比 | 输入、约束、指标及信息权限可比时才标提升比例；否则仅并排展示并说明差异 |

缺候选、概率、报价等细节时显示“未记录”，不从总结果编出过程。不要求为此补建统一审计平台；挑选少量有完整记录的示例即可。

## 7. 简明验收

1. 启动后直接进入展示页，不出现登录、首页门户或管理菜单。
2. 加载一份数据，选择CAPA可以计算；选择RL-CAPA并加载兼容模型可以推理，不进行训练。
3. 一个小场景能完整播放、暂停、单步、重置和拖动；地图、详情、累计指标一致。
4. 至少一件包裹能讲清本地选择与两层竞价，RL示例能显示两个阶段的真实动作。
5. 结果页数值与原始算法输出一致；切换数据或模型不会残留旧结果。
6. 加载预计算记录可以直接展示，清楚标注回放；只有汇总数据时只画结果图。
7. 数据/模型加载失败、空候选和无完成任务时有简短可读提示。
8. 在实际演示电脑完成一次从加载到图表的操作，确认文字、图例和按钮可读可用。

先用20–100任务作为过程展示候选规模，按实际耗时与清晰度选择；大规模只加载已有结果。这里不承诺未经测量的帧率、毫秒延迟或实时大规模计算能力。统计实验和论文补充论证仍可用原项目脚本完成，不转成页面开发要求。
